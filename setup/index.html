Install Family Bill Tracker, add your family, and update it later while keeping your accounts and records. Take it one step at a time.

Before you start

Have your Synology administrator account, a NAS with Container Manager support, and a trusted HTTPS address for the app. The intended model is the DS923+. This guide does not install Docker remotely or alter NAS settings for you.

01

Prepare your Synology

  1. Sign in to your NAS's DiskStation Manager (DSM) using your browser.
  2. Open Package Center. Search for Container Manager and install it. If it isn't available, confirm the NAS model and supported DSM version before continuing.
  3. Open File Station. In the shared docker folder, create a folder called fbt. If the docker share does not exist, create it using your normal NAS administration process.
  4. Copy this project's source files into that folder. The folder should contain compose.yaml, Dockerfile, manage.py, config, tracker, templates, and static. Keep the subfolders intact.

These instructions apply to the app source checkout or its downloaded ZIP, not just the PDF overview. The NAS needs internet access to download the container images and Python packages.

02

Create your settings file

New installation only

If your app is already running, keep its existing .env. Do not generate replacement passwords or keys for a routine update. Use the update walkthrough instead.

Choose the address your family will use. This form generates random credentials and push keys on this device, then downloads a file called .env. It does not upload settings or connect to the NAS.

Upload the downloaded .env file into the same fbt folder as compose.yaml. Some browsers save the download as env.txt; rename it to .env before uploading. On Windows, turn on File Explorer → View → Show → File name extensions so you can remove .txt. Your file browser may hide dotfiles. Make sure the name is exactly .env, without .txt at the end.

Keep the setup code handy

Open your local .env file and find FBT_SETUP_TOKEN. You'll paste its value into the app once to create the first administrator. The app never asks for your DSM password.

Generation requires Web Crypto. If your browser blocks it when opening a downloaded file, use this guide on localhost or ask a trusted person to run the documented configuration helper.

03

Start your app's containers

  1. Open Container Manager → Project → Create.
  2. Name the project fbt, and select the docker/fbt folder you prepared.
  3. Choose the option to use an existing Compose file, and select compose.yaml. Keep the .env beside it so Compose can load its values.
  4. Build and start the project. The first build takes longer because it downloads dependencies.
  5. Watch the project details. db should become healthy, init should finish with exit code 0, and web and worker should stay running. The init container stopping successfully is expected.

The app listens on port 8787 on the NAS loopback interface only. It is intentionally unavailable as http://NAS-IP:8787 from a phone. The next step creates the secure entry point.

What is each component for?
  • db: PostgreSQL stores your family's records in a persistent Docker volume.
  • init: Applies database migrations before the app starts.
  • web: Serves the app.
  • worker: Generates recurring bills, checks due payments, and sends configured reminders.
04

Give your family a secure address

The hostname entered above must resolve to your NAS from your home network, and have a certificate your phones trust. A certificate error is a setup problem to fix; do not bypass it.

  1. In DSM, open Control Panel → Login Portal → Advanced → Reverse Proxy (the exact label may vary with DSM).
  2. Create a rule for your app: source protocol HTTPS, source hostname matching the address in your .env, and the source port from that address (normally 443).
  3. Set the destination to HTTP, hostname 127.0.0.1, port 8787.
  4. Ensure the proxy overwrites the X-Forwarded-Proto header with https. The application trusts this header only because its port is restricted to loopback.
  5. Under Control Panel → Security → Certificate → Settings, assign the trusted certificate matching this hostname to the rule.
  6. Join home Wi-Fi on your phone and open the HTTPS address. You should see the first-time family setup screen.
Don't have a hostname or certificate?

Pause here and ask your NAS or network administrator to arrange home DNS and a trusted certificate. Synology DDNS or a domain you control may be options. The right method depends on your router and domain. This application does not automatically provision certificates or require opening your NAS to the public internet.

A private IP with an untrusted certificate is not enough for iPhone PWA features. Keep the database and DSM management interface private. Do not forward database ports on the router.

05

Make it your family's space

  1. Enter the setup code from .env, your family name, a username, and a password of at least 12 characters.
  2. Open Setup & devices. Name the NAS and save the home server address for reference. Changing this label does not change server routing.
  3. Use Manage family accounts to create a separate username and password for each family member. Leave staff and superuser permissions off for ordinary members. All accounts on this deployment share the family records.
  4. Add one small test bill, record a partial payment, and confirm another family member sees the same balance.
  5. Open System status. Check the live database and worker results. Push keys being configured does not prove notifications were received; run a device test next.

Once the first account exists, the setup form closes. Keep .env securely backed up. Removing or changing the setup code later does not remove the family account.

06

Add the app to your phones

iPhone (iOS 16.4 or later)

Open the HTTPS address in Safari → Share → Add to Home Screen. Open the new icon, sign in, and go to Setup & devices → Enable on this device. Allow notifications, then choose Send a test and check that it arrives.

Android

Open the HTTPS address in a supported browser such as Chrome. Choose Install app or Add to Home screen from the browser menu. Sign in and enable notifications in Setup & devices.

Review bills offline

  1. While connected, open Setup & devices → Save bills on this device. Use a trusted, screen-locked device.
  2. Open the installed app once while connected so its shell can be saved.
  3. Disconnect from your home network and open the app. It should show a timestamped, read-only snapshot.
  4. Reconnect. The app checks reachability about every 30 seconds, then offers Update saved bills. Review that update before recording payments.

Saved snapshots expire after seven days. Offline copies contain family financial information in browser storage; they are not protected from someone using the same unlocked browser profile. Signing out removes the saved copy. If you sign out offline, the app asks you to reconnect to finish ending the server session.

Reminders while you are away

Once subscribed, your phone can receive internet push messages while the NAS is online, even if the app is closed. Opening the bill or refreshing records still needs access to the home server. Phone settings and internet outages can delay delivery.

07

Update an existing installation

You can keep developing the app after installing it on the NAS. Updates replace application code and containers while keeping your family accounts, records, and settings.

Keep these parts separate
  • Application files and containers: replaced or rebuilt for a new version.
  • The existing .env: kept in the same project folder on your NAS. It contains the database password and app/notification keys.
  • The existing PostgreSQL volume: kept attached to the same project. This stores accounts, bills, payments, and history.

A routine update does not require resetting accounts, regenerating .env, removing sample records, or creating a new database.

  1. Choose a version and a quiet time

    Use a reviewed release or the latest merged main version from your repository. Read its release and migration notes first. Ask the family to pause entering payments. Record the current version and retain a copy of its app files.

  2. Pause writes and back up

    In Container Manager, stop this project's web and worker containers. Leave db running until the backup finishes. Back up PostgreSQL and the current .env, then copy both to a protected location outside the NAS. CSV exports and RAID are not a complete backup.

    Database backup using the NAS terminal

    Use a NAS/Linux terminal with permission to run Docker, opened in your existing fbt project folder containing compose.yaml. These are not Windows PowerShell commands. Ask the person managing your NAS to handle the backup if needed.

    Create a protected staging folder if it does not already exist:

    mkdir -p backups

    Use a new filename for each update. Replace YYYYMMDD below; do not overwrite your only backup:

    docker compose exec -T db pg_dump -U fbt -d fbt -Fc > backups/fbt-before-update-YYYYMMDD.dump

    Confirm that the command finishes without an error; a file merely existing does not prove success. Securely copy the dump and the existing .env off the NAS. Follow the backup/restore reference in docs/OPERATIONS.md in your downloaded project, including testing restoration separately.

  3. Replace code in the same folder

    Once the backup is safe, stop the remaining project containers. Download the selected version, extract it into a temporary folder, and copy the application files into the existing docker/fbt folder. Preserve the original .env and backups.

    Keep the same Compose project name, database volume, app address, certificate, and reverse-proxy rule unless the release specifically requires a change. Do not delete the project folder or choose an option that removes its volumes/data. A PostgreSQL major-version change needs its separate database-upgrade instructions.

  4. Build the existing project

    Open Container Manager → Project, select the existing fbt project, and choose its Build action using the updated compose.yaml. Build prepares images/containers without starting them; exact menu labels can vary by version. A simple Restart does not rebuild the app from new source files.

    If the release needs new settings, add them to the existing .env while preserving its secrets and database password. Rebuilding/recreating the app containers makes them load those settings.

  5. Run migrations before starting the app

    From the project's containers, start db and wait until it is healthy. Start the newly built init container, check its fresh logs, and wait for exit code 0. An old successful init log is not proof the new migration ran. Only then start web and worker.

    If init fails, keep web and worker stopped and inspect its logs. Do not bypass the failure, delete the database, or generate new credentials to hide the error.

    Equivalent update commands from the project folder

    After a successful backup and code replacement, start the existing database:

    docker compose up -d db

    Check its status and wait for db to become healthy:

    docker compose ps

    Build the shared application image:

    docker compose build web

    Run migrations in a fresh one-off init container:

    docker compose run --rm init

    Continue only if init succeeds with exit code 0. Then start/recreate the application services as needed:

    docker compose up -d web worker

    Check all components, including the successfully completed init service:

    docker compose ps -a

    Stop on any failed command. Compose recreates services when their image/configuration changes and preserves mounted volumes. Do not add volume-removal options to update commands.

  6. Check accounts and records

    Open the same HTTPS address on home Wi-Fi and sign in with the existing administrator. Check System status, including the database, worker, and audit logging. Compare existing bills, loan balances, and paid-history entries with the pre-update records. Check an ordinary member account and send a notification test.

    Asked to create a family again?

    Stop web and worker. Do not register another administrator yet. Verify the original project name, .env, and database volume are still being used. A new setup screen can indicate an empty database connection, not that the original database was erased.

  7. Refresh phones and saved copies

    While connected to home Wi-Fi, reload the browser page or close and reopen the Home Screen app. Accept Update saved bills if offered, or use the app's refresh control. Check the saved-copy timestamp when offline viewing is enabled. Keep the same app address; an update normally does not require uninstalling the app, clearing browser storage, or signing out.

    Repeat this process for later versions, keeping the latest working backup separate from the NAS.

What if I need to return to the old version?

Replacing files alone does not undo a database migration. Some migrations refuse a downgrade after new data has been recorded. Keep the failed app stopped, read its migration notes, and use the matching application version and complete database backup through a verified restore process. Test restoration separately before replacing the only live database, with reminders paused in the restore environment.

Reference: Synology Container Manager projects and Docker's one-off run command. This guide describes the workflow; it does not execute NAS commands.

If something isn't working

The app won't open

Check home Wi-Fi, hostname resolution, the certificate, and the NAS reverse proxy rule. Check Container Manager for stopped containers. A browser error is not proof the bills database was lost.

Container build or startup failed

Check NAS internet access and free disk space. Confirm .env is beside compose.yaml and contains every generated value. Inspect init logs for migration errors and db health. Do not delete the database volume to troubleshoot.

Invalid host or CSRF error

The exact HTTPS hostname must be listed in FBT_ALLOWED_HOSTS and its origin in FBT_TRUSTED_ORIGINS. If you change .env, recreate the web and worker containers using Container Manager's project rebuild action so they load the new settings. A simple process restart may retain old values.

Worker is unhealthy

Open the worker container logs. Ensure it can reach db, uses the same settings as web, and is running the reminder_worker command. A heartbeat older than three minutes is unhealthy; it may also mean a very long reminder cycle.

No offline copy appears

Enable offline viewing while connected. Use the same installed app and browser profile, a trusted HTTPS origin, and available storage. Private browsing, cleared browser data, storage eviction, an expired snapshot, or signing out can remove the copy.

Notifications aren't arriving

Use the installed Home Screen app on iPhone. Check notification permission and Focus settings. Look at System status, confirm all VAPID settings exist, and send a test. Keys can be configured even when a network or device issue prevents delivery.

How do I update without losing accounts or bills?

Follow the update walkthrough above. Keep the original .env and PostgreSQL volume; do not create a fresh project or database for an update.

How do I back up and restore?

Follow docs/OPERATIONS.md in the project. Back up PostgreSQL and .env to a protected destination outside the NAS, and test restoration in a separate environment. RAID and CSV export are not a full recovery plan.
