# Family Bill and Loan Tracker

The original application idea is by Chris Daniel Apin (111chap). The proposed technology stack and supporting information in this document were generated by Codex based on his idea and requirements.

## Purpose

Replace a manually maintained spreadsheet with a shared, phone-friendly application that tracks unpaid bills, payment due dates, and loan repayments. Remind family members when payments are approaching or overdue.

The family enters bills and records payments manually. Bank connections, automatic payment detection, and payment processing are outside the scope.

## Intended users and devices

- Family members using a mix of Android phones and iPhones.
- Individual accounts with access to shared family records.
- A responsive interface that also works on a computer.

## Hosting and installation

The family NAS hosts the application, database, and reminder worker through Docker Compose. The exact NAS model, processor architecture, available memory, and Docker support must be confirmed before implementation.

The proposed mobile experience is a Progressive Web App (PWA): an installable website with a Home Screen icon. A public App Store release is not required for this approach.

On iPhones, Web Push requires iOS 16.4 or later, installation on the Home Screen, and notification permission. Android users would also install the web app and grant notification permission. Device compatibility should be tested on the family's actual phones.

The app needs HTTPS. Access outside the home requires a suitable remote access arrangement, to be selected after checking the NAS and home network.

## First-version features

| Feature | Expected behavior |
| --- | --- |
| Dashboard | Show overdue bills, upcoming payments, and totals due in a selected period. |
| Bills | Record title, amount, due date, category, notes, and responsible family member. |
| Recurring bills | Generate the next occurrence from a recurring schedule. For variable amounts, request the new amount before treating the bill as finalized. |
| Loan repayments | Record an agreed repayment schedule, installments, and payment history. |
| Payment recording | Manually record amount paid, payment date, and the family member who entered it. |
| Shared status | Let family members see whether a bill is unpaid, partially paid, paid, or overdue. |
| Reminders | Support configurable reminders before the due date, on the due date, and after it becomes overdue. |
| Notification preferences | Let each person choose which shared bills generate notifications on their devices. |
| History and corrections | Preserve who recorded or corrected a payment and when. |
| Export | Export records to a spreadsheet-compatible CSV file. |

Loan tracking initially follows manually entered, agreed amounts and schedules. Interest calculations, penalties, changing rates, and early-settlement calculations require separate requirements if needed.

## Example journey

1. A family member adds an electricity bill for PHP 2,500 due November 20.
2. They select reminders three days before the due date and on the due date.
3. Subscribed family members receive reminders on their phones.
4. Someone pays the bill outside the application.
5. That person records the payment in the app.
6. Everyone sees the updated status, and future unpaid-bill reminders for that occurrence stop.

## Proposed technology stack

| Layer | Technology | Reason |
| --- | --- | --- |
| Interface | Django templates, HTMX, and responsive CSS | Support forms, dashboards, and updates without maintaining a separate frontend application. |
| Installable app | Web app manifest and JavaScript service worker | Provide the Home Screen experience and receive Web Push events. |
| Backend | Python and Django | Manage accounts, permissions, validation, recurring schedules, and payment records. |
| Database | PostgreSQL | Store shared records and durable reminder state. |
| Push delivery | Standard Web Push through `pywebpush`, using VAPID credentials | Send notifications to device subscriptions without a bank integration. |
| Reminder worker | Separate Python process using the same Django code | Check persisted reminder schedules approximately every minute. |
| Deployment | Docker Compose | Configure the application, database, worker, networks, and persistent storage together. |
| HTTPS | NAS reverse proxy or Caddy | Provide a secure browser connection; final choice depends on the NAS and access setup. |
| Backup | Scheduled database backups copied outside the NAS | Allow recovery if the NAS or its storage fails. |

Select supported dependency versions and container images compatible with the NAS when implementation begins.

## Reminder delivery

```text
Bill and schedule saved in PostgreSQL
                |
                v
Reminder worker checks for pending reminders
                |
                v
Browser platform's Web Push service
                |
                v
Subscribed family phones
```

- Store reminder schedules and delivery attempts in the database.
- Use a single active scheduling process initially, plus database safeguards against duplicate processing.
- Retry temporary delivery failures and retire expired device subscriptions.
- Recheck payment status before sending an unpaid-bill reminder.
- Define how reminders missed during an outage are handled, avoiding a burst of stale notifications after restart.
- Keep an in-app list of upcoming and overdue payments; push delivery is not an exact-time guarantee.

The NAS needs internet access to send Web Push messages. Notifications pass through browser platform infrastructure, including Apple's infrastructure on iPhones. Notification receipt does not require the app to remain open, but opening the bill requires connectivity to the NAS.

The first version supports online editing. It should display a clear connection message when the NAS is unavailable. Offline editing and synchronization are deferred.

## Data and access principles

- Store money as decimal values or integer minor units, never floating-point values.
- Treat bill due dates as calendar dates and reminder times using an explicit timezone; Asia/Manila is the initial assumption.
- Keep recurring templates separate from individual bill occurrences and payment records.
- Calculate balances from recorded obligations and payments, with clear rules for partial payments and corrections.
- Require sign-in and enforce family membership on every shared record.
- Keep database access private to the deployment network and keep secrets outside source control.
- Offer discreet notification text that avoids showing amounts or loan details on a locked screen.
- Test restoring backups. CSV export is useful for portability but does not replace a full database backup.

## Scope boundaries

Included: manual entry, shared tracking, recurring schedules, payment history, and notifications.

Deferred: bank integrations, automatic payment detection, payment processing, native mobile apps, offline editing, receipt recognition, and complex lending calculations.

## Decisions still needed

1. NAS model, CPU architecture, memory, and container support.
2. Access only at home or also while away.
3. Remote access method, HTTPS arrangement, and whether a domain is needed.
4. Actual phone operating-system versions.
5. Number of family members and whether any records should be private.
6. Currency, reminder times, quiet hours, and overdue reminder frequency.
7. Loan rules, including partial payments, fixed installments, and any interest already included in the schedule.
8. Backup destination and retention period.

## Suggested delivery stages

1. Confirm the hardware, access arrangement, and payment rules.
2. Build accounts, bills, manual payments, and the dashboard.
3. Add recurring bills and loan installment schedules.
4. Add PWA installation, device subscriptions, and reminder delivery.
5. Test on the family's Android phones and iPhones, including worker restarts and payment/reminder timing.
6. Configure backups, verify recovery, and trial the app with a small set of real bills.
